# 飞返竞技场 · 游戏与开服手册

**想先看一局？** 解压 Windows 游戏包，双击 `watch-duel.cmd`。它会在实时 3D 客户端里播放双湖的 Astra 对 Fable 原回放：第 383 步 Fable 获胜。计时条显示比赛剩余时间；退五秒、换视角和慢放都不会重算选手决策。想亲自上场，双击 `Flyback.exe`，选择「快速挑战」，把一个席位设为真人，其余席选 AI。

### 选比赛、选图、控制人物

- 对决支持 2、3、4 个独立席位。单人可对阵 1、2、3 位 AI；联机可让真人占任意空缺的真人席，最多 4 人。也可把所有席位设为机器人，自己当观众。13 位原选手运行的是本地选手程序，不需要模型账户或 API Key。
- 地图先按人数筛选。指定只打一张，轮换按所选顺序，随机将所选地图洗牌。可统一设置每图局数，也能覆盖具体地图（每图 1–99 局）。每局记录排名与击杀；该图局数打满才换图，系列赛结束展示累计成绩。
- 这版共有 12 张地图。其中新增的**潮汐船闸、赤陶窑场**支持双人或四人；三人可选**风车岬、月井庭**。船闸有横桥和外堤两个进攻方向，窑壁可挡镖；风车岬三路可换线，月井庭的井口始终不能站，最后沿井沿交战。
- 出镖是竹棍划过空气的声音，实打命中是短促的拍击，挡镖和双镖相撞各有不同的金属声。在「操作与设置 → 比赛音效」可以调音量或静音。声响跟随本席能知道的事件，空挥不会响命中声。
- WASD 移动、鼠标瞄准、左键出镖、右键近战、空格冲刺、R 召回。Esc 进对局菜单，P 暂停或发起投票，F11 全屏。手柄的移动、瞄准与扳机映射见游戏内「操作与设置」。
- 有真人参赛默认 **0.8×**；全 AI 表演赛默认 **1×**。每局开场先看见地图和自己的角色，再倒数 **3、2、1**；开战前不会移动、出镖或消耗局时。旧回放直接播放，不另加倒计时。
- 本地非服务器比赛可选 0.5×、0.8×、1×、2× 和暂停。联机按开局阵容固定倍率，即使只有一个真人，也要用公开表决暂停或恢复；赞成票必须超过当前真人参赛者的一半，观众不能投票。
- 原规则每个游戏秒仍是 20 步；0.8× 时每个现实秒推进 16 步。真人看到当前步可见的对手和飞镖，命中与死亡按同一步反馈。只有 AI 看见的敌情比裁判晚四步（0.8× 时为 250 ms，1× 时为 200 ms），用来模拟人的反应时间。草丛仍能藏人。客户端单独绘制中间帧。出局回看用本席真正出局前后的权威轨迹；多人局提前出局不会提前得到三秒观战延迟内的情报。服务器不因一个人在看回放而停赛。

### 和朋友玩：两种房间，同一个准备厅

**临时开一局**：在联机大厅创建局域网房间，决定人数、AI、地图、密码，系统带房主进入准备厅并显示实际游戏 UDP 端口。局域网可以自动发现；跨网时用支持 **UDP** 的端口映射或内网穿透，把外部游戏地址交给朋友。房主退出程序后该局域网服务结束。

**在专服建房**：在大厅添加专服地址。列表里的每一组就是一台真实专服，可展开查看它当前的房间，再选择加入、观战或在其上开一间新房。多个房间共用专服的游戏端口；桌面建房者是房间主持人，裁判始终在专服运行。首次连接核对服务器显示的公钥指纹，再输入房间密码。已保存的指纹变更时，先向服主确认。

其他真人先进入准备厅，入座、准备，房主开局。开打后新加入的一律先观战。观众不占参赛席；专服上限为 `-1` 时不设人数限额，`0` 时不接新观众。降低人数上限不踢已入场观众；公网承载量仍取决于带宽和机器。控制台与 WebUI 会显示实际负载。

### 运行 Windows 或 Linux 专服

**已有服务器升级**：保留原来的 `server.toml` 和运行数据，尤其是 `storage.data_dir` 下的 `identity/server.crt`、`identity/server.key`。Windows 默认是配置文件旁的 `data/identity`；Ubuntu systemd 安装为 `/var/lib/flyback/identity`。不要清空身份目录后再启动新程序，否则既有客户端会拒绝陌生的服务器指纹。

Windows 用独立专服包，不需要显示器、Godot、Python、Blender 或编译器。解压到服务账号可写的目录，在该目录的 PowerShell 中运行：

```powershell
.\arena-server.exe --config .\server.toml check-config
.\arena-server.exe --config .\server.toml admin init
.\arena-server.exe --config .\server.toml
```

首次初始化会让你在终端输入两遍管理员密码。Linux 专服包面向 **Ubuntu 24.04 x86_64**，安装随包说明中的发行版依赖和 MsQuic 包后使用 `./arena-server`。要运行 AI，请按包内 Linux 指南使用受委托的 cgroup v2 服务；它与 Landlock、seccomp 一起限制选手进程。仅换成 root 或关闭隔离不是替代办法。

游戏地址看启动输出的 **UDP 端口**；管理页面用的是另一个 **TCP 地址**。示例为游戏 `0.0.0.0:27860`、WebUI `127.0.0.1:27861`，均可由服主调整。外部管理可通过 HTTPS 反向代理并设置 `public_origin`，也可用内置 HTTPS 配置证书和密钥。告诉玩家游戏地址，而不是管理页地址。控制台命令：`rooms` 列房间，`drain` 停接新房新赛，`resume` 恢复接纳，`stop` 关闭服务。

| 配置（server.toml） | 对服主的影响 |
|---|---|
| `server.listen` / `server.advertise` | 监听地址、可提供给外部玩家的地址；修改监听需重启 |
| `server.max_rooms` / `max_active_matches` | 同时保留的房间数 / 可同时比赛的房间数 |
| `server.max_spectators_per_room` | 每房的硬上限，管理台可以给单房设置更小的额度 |
| `match.spectator_snapshot_hz` / `server.egress_budget_kbps` | 正常观战刷新率 / 全服出站预算（0 不限）。持续超预算时先压低观战频率，再限制新观众；参赛席仍逐步收到状态 |
| `server.idle_room_ttl_seconds` | 空房保留秒数；0 表示房间空后立即回收 |
| `storage.data_dir` | 服主的账号、身份密钥、日志和回放所在目录；相对路径基于配置文件 |
| `replays.enabled` / `retain_days` / `max_disk_mib` | 是否归档、保留天数和磁盘预算；`logs.rotate_mib` / `keep_files` 控制日志轮换 |

WebUI 区分管理员、操作员和只读角色。配置写入要带当前版本；多人同时编辑时，过期写入会被拒绝。CLI `admin init|reset --user 名称 --role admin|operator|viewer` 可开账号或换凭据。备份配置及运行数据目录，尤其是服务器身份密钥：更换它会改变玩家需要核对的指纹。

### 回放、第三方 AI 与协议

客户端可打开原版 `DART-REPLAY 2` 文本和本作 `.fbar` 文件。「本机回放」读取当前用户的归档。Windows 在 `%LOCALAPPDATA%\FlybackArena`，Linux 在 `$XDG_DATA_HOME/flyback-arena`（未设置时是 `~/.local/share/flyback-arena`）。专服回放随专服配置存放。

QUIC/TLS 1.3 负责传输加密。动作和位置走数据报，房间命令、结算与回放走可靠流；观众共享同视角的编码而不共享密文，只有体积值得的公开大消息才尝试 Zstd。协议头 `FBAR 1.0`、`profile=0`、`base_id=flyback:vanilla` 明确表示原版；不支持的必需扩展会在进入比赛前被拒绝。此版不会下载或运行玩家传来的 Mod 或选手程序。
