# 权威裁判与选手包

`flyback_game` 在同一份整数规则上跑真人、AI、录像。发行版共有 **12 张地图**：六张保留的原作地图，加上 `maps/` 下六张本作地图。八张支持双人和四人，四张专为三人混战设计。`data/bots` 放当前平台独立、静态链接的 13 名正式选手。发布时复制安装树，不要把 Windows 的选手包发给 Linux。原参赛代码和地图保留在仓库原路径，无需修改。

**本地登记社区选手**：服主检查来源、协议和再分发许可，离线准备只认 `DART 2` 的静态 x64 程序。把它放到 `data/bots/community-neon.exe`（Linux 无扩展名、设为可执行），并在该目录的 UTF-8 `community.json` 写入：

```json
[{"id":"community-neon","name":"Neon"}]
```

清单仅允许 `community-` 前缀、ASCII 小写、数字与连字符，通过 ID 解析同目录的文件，不接受远程路径和玩家上传。无二进制的条目显示不可用，不能用替补假装已经参赛。目录中的 `available` 表示已发现本平台二进制，沙箱启动是准备厅的进一步检查。

**运行边界**：Windows 使用无 capability 的 AppContainer、只读选手副本、独立 Job（单进程、1 GiB）、最小环境和受限继承的管道。Linux x86-64 要求内核启用 Landlock、seccomp、cgroup v2，宿主可创建带 memory 与 pids 控制器的子组。可将环境变量 `FLYBACK_CGROUP` 设为 **已委托给服务账号**的空内部 cgroup 路径，里面启用 `+memory +pids`（cpu 计量读取每子组 `cpu.stat`）。若使用 systemd，给宿主启用 `Delegate=yes`，把宿主留在与 Bot 子组并列的叶组；不要把别的服务加入这棵树。不要直接将整个 cgroup 文件系统改成所有人可写。加载失败会阻止该场带 Bot 的比赛；纯真人局无需沙箱资源。Linux 包须连同 `data/bots/arena-bot-guard` 一起交付；守卫在执行选手之前收紧进程、地址空间、文件描述符限制，使用 Landlock 只许可执行本选手，再启用默认拒绝的 seccomp 过滤。任一层不可用就不运行选手。

安装树的 `examples/flyback.service` 和 `run-delegated` 给出完整的 systemd 入口。将受保护的配置放在 `/etc/flyback/server.toml`，其中可写的数据目录指向 `/var/lib/flyback`，按实际安装目录改写示例内的 `/opt/flyback`。该专用服务账号应能读资源与配置；不要让它能改已审核的 Bot 二进制或守卫。启动脚本仅调整自己所在且已获委托的 cgroup。

**计时**：载入同时启动和预热所有 Bot，首步最多 5 s 墙钟 / 1000 ms CPU。常规步使用同一批次并发询问所有仍存活的 Bot，在 30 ms 墙钟软截止内收集，每席 10 ms CPU；偶发迟到/非法用中立输入，迟到行不会顺延套给下一步。持续无响应或累计 20 次错误退役该席。每房应在独立工作上下文推进，别在网络或 UI 线程调用。公开暂停时不调用 `tick`，不会派出新观察。

**坐标与视角**：X 向右、Y 向下，一格 500 mm；角度单位为 0.01°。席位从零开始。真人收到 `snapshot(seat)` 的当前步合法视野：可见对手、飞镖和命中同步更新；草丛里未暴露的角色与手中镖不发坐标，掉在地上的镖仍公开。事件按发生瞬间的可见性裁剪，不靠结步后的尸体反查隐藏目标或凶手。原版 AI 的 `observe(seat)` 和切到该 AI 席位的观战视野仍使用四步前的对手状态，自己是当前步。新比赛清单分别记录 `human_observation_delay_ticks` 和 `ai_observation_delay_ticks`，旧回放保留原资料。事件 ID 使用轮次、动作 tick 和 ordinal，状态帧 tick 指该动作完成后的步界。`snapshot(-1)` 只供裁判和延时观战；主持端仍按独立的现实时间水位释放观战快照、击杀片段和成绩。

**回归**：以 `BUILD_TESTING=ON` 构建后运行 `ctest -R flyback_game`。`flyback_game_test data /path/to/meow-ai-arena/boomerang/replays --bots` 重跑 117 场逐步逐字段对照、13 场三席和 13 场四席轮座。也可使用 `flyback_game_test data --bot-startup` 逐一检查 13 名选手在本平台沙箱内的启动、预热和常规决策。不同时间预算/机器上的 AI 可能重新选招；确定性回归只重放裁判已接受的动作。

视角夹具覆盖真人移动、进草、出手暴露、飞镖、落地镖与死亡：第三人不能从结步后才公开的尸体补出草中受击者。在已配置 Bot 沙箱的环境运行 `flyback_game_test data --bot-pov`，还会用同局的真人和 Fable 两席，核对真人动作即时、Fable 席看到的移动和动作事件恰好晚四步。

三席地图数据键为 `MODES_EXT ffa3` 和 `SPAWN_3`；格网与塌陷图仍是原格式。原 `MODE=2` 继续表示八人团战的历史协议，不能重解释为“三人”。发行用 MIT 许可证随附上游版权。

### 三席出生位置的依据

`tests/trio_routes.py` 按八方向可走格计算从三个实际出生点到中心的最短路线（斜向不可穿墙角；含起、终格中心的偏移）。三岔湾为 **5.109 / 5.388 / 5.388 m**（最大比最小长 5.47%），灯塔环礁为 **5.707 / 5.902 / 5.902 m**（3.42%）。

同一 Fable 占三席，种子 1–180 连续进行每图 180 局，同步并列第一平分 1 份。最初把席号永久绑在物理出生位时，三岔湾第三席只占 **25.83%**。成品把物理出生位按种子循环轮换，不改变二/四人原赛或任一席位的裁判规则。用 `flyback_game_test data --balance 180` 实测，三岔湾三席第一份额分别为 **30.56% / 38.89% / 30.56%**，灯塔环礁 **26.94% / 36.94% / 36.11%**。两张图的实际出生位份额分别为 **35.56% / 36.39% / 28.06%** 与 **28.06% / 36.39% / 35.56%**。这是同款 AI 的一组实战记录，随机抽图、不同玩家策略和挂钟 CPU 预算都会影响实际胜率。

### 四张新图怎样打

| 地图 | 席位 | 路线与终局 |
|---|---|---|
| 潮汐船闸 `tidelock` | 2 / 4 | 两条狭水渠把地图拆成三片。中央闸桥最快暴露在交叉火力里，两端堤坝都能绕行；退潮后决战在中间闸台。 |
| 赤陶窑场 `kiln` | 2 / 4 | 四座破窑各有一个坑和一段弧墙。沿外廊能从侧边发起反击，穿过无掩体的中央场地则更快；缩圈迫使双方离开窑壁。 |
| 风车岬 `windrose` | 3 | 三条宽叶以同一方向扭入中心。走径向捷径抢轴心，或走跨叶环道转到对手背侧；最终只剩轴心圆台。 |
| 月井庭 `moonwell` | 3 | 中心是井孔。外侧石屏和草丛可以伏击，但终局只剩井沿一圈；顺时针、逆时针均能绕过对手，击退也可能把人送入井内。 |

四图每格 0.5 米，共七波塌陷。`tests/new_map_routes.py` 将角色半径 0.4 米纳入寻路，检查各波后能安全站立的格中心是否连通，并单独封住船闸中央桥、窑场中央空地和风车轴心来验证绕行路线；月井则检查最终井沿的南北半圈能否分别通行。`tests/trio_routes.py` 测得风车岬三席至中心距离为 **6.047 / 6.021 / 6.093 米（相差 1.20%）**，月井庭三席至最终井沿为 **2.769 / 2.875 / 2.875 米（相差 3.83%）**；两图目标不同，距离不能互相比速度。

Windows 原生裁判检查了六种合法“地图 × 席数”组合在种子 0–128 的全部出生点；角色都未撞墙、落坑或重叠。`flyback_game_test data --new-map-bots` 让 Fable、Astra（四席再加入 Sol、千问，三席再加入 Sol）实打这六场；种子 7 的这一轮均正常结算，无 Bot 故障。路径差、一次对局的胜负和长期胜率不是同一指标。
